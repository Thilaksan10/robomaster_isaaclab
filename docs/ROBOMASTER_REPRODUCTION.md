# Robomaster Instructions

This repository contains the implementation used to train and evaluate the Robomaster motion controllers.

The submitted repository does not include:

* robot simulation assets
* trained model checkpoints
* generated racetrack CSV files
* generated edge-case CSV files
* benchmark CSV files
* evaluation plots

The robot assets are provided separately. All other generated files can be reproduced using the scripts contained in this repository.

---

## 1. Add the Robot Assets

Before training or evaluation, create the following directories:

```text
assets/
├── robomaster/
└── robomaster_optimized/
```

Place the USD files of the **non-optimized simulation model** inside:

```text
assets/robomaster/
```

Place the USD files of the **optimized simulation model** inside:

```text
assets/robomaster_optimized/
```

---

## 2. Train the Controllers

Training is performed using:

```text
trainings_script.py
```

For each simulation model, the following controller configurations are trained:

* fully learned policy controller without domain randomization
* fully learned policy controller with domain randomization
* hybrid offset controller without domain randomization
* hybrid offset controller with domain randomization

Each configuration is trained using the seeds:

```text
0
24
42
```

This results in:

```text
2 controller types
× 2 randomization configurations
× 3 seeds
= 12 policies
```

for each simulation model.

Since both the non-optimized and optimized models are used, the complete training procedure produces **24 trained policies**.

### 2.1 Non-Optimized Model

Run:

```bash
python trainings_script.py
```

This trains the 12 policies using the non-optimized Robomaster simulation model.


Example:

```text
2026-09-25_14-00-00_policy_no_rand_seed_0
2026-09-25_14-05-00_policy_rand_seed_24
2026-09-25_14-10-00_offset_rand_seed_42
```

### 2.2 Optimized Model

Run:

```bash
python trainings_script.py --optimized
```

This trains another 12 policies using the optimized Robomaster simulation model.

Experiment names generated by these runs contain `optimized`.

Example:

```text
2026-09-25_14-59-49_policy_no_rand_optimized_seed_0
2026-09-25_15-03-39_policy_rand_optimized_seed_24
2026-09-25_15-10-12_offset_rand_optimized_seed_42
```

---

## 3. Training Logs

Each execution of `trainings_script.py` creates a JSON log describing the complete training batch.

After training both simulation models, two JSON logs are available:

* one for the non-optimized training runs
* one for the optimized training runs

Each run contains information such as:

```json
{
    "policy_mode": "policy",
    "seed": 0,
    "randomization_mode": "no_rand",
    "experiment_name": "2026-09-25_14-59-49_policy_no_rand_optimized_seed_0",
    "status": "success"
}
```

For the later evaluation, the important fields are:

```text
experiment_name, policy_mode, seed and randomization_mode
```

The experiment name identifies the corresponding RL-Games training directory and trained model.

## 5. Configure the Benchmark Scripts

Before running the evaluations, the trained models must be specified in:

```text
racetrack_benchmark_script.py
edgecase_benchmark_script.py
```

Both scripts contain two arrays:

```python
NON_OPTIMIZED_MODELS = [
    ...
]

OPTIMIZED_MODELS = [
    ...
]
```

The experiment names generated during training must be inserted into these arrays.

### 5.1 Non-Optimized Models

Use the JSON log generated by:

```bash
python trainings_script.py
```

Each entry in the JSON log describes one trained model. For every entry, create one corresponding `Model(...)` object inside:

```python
NON_OPTIMIZED_MODELS = [
    ...
]
```

The JSON fields are mapped to the `Model` object as follows:

| JSON field           | `Model` field            | Mapping                                  |
| -------------------- | ------------------------ | ---------------------------------------- |
| `experiment_name`    | `run_id`                 | Copy directly                            |
| `policy_mode`        | `controller`             | Copy directly (`"policy"` or `"offset"`) |
| `seed`               | `seed`                   | Copy directly                            |
| `randomization_mode` | `training_randomization` | `"no_rand"` → `False`, `"rand"` → `True` |

For example, the following JSON entry:

```json
{
    "policy_mode": "policy",
    "seed": 24,
    "randomization_mode": "rand",
    "experiment_name": "2026-09-25_14-10-00_policy_rand_seed_24",
    "status": "success"
}
```

has to be converted to:

```python
Model(
    controller="policy",
    run_id="2026-09-25_14-10-00_policy_rand_seed_24",
    seed=24,
    training_randomization=True,
),
```

Similarly, an entry such as:

```json
{
    "policy_mode": "offset",
    "seed": 42,
    "randomization_mode": "no_rand",
    "experiment_name": "2026-09-25_14-20-00_offset_no_rand_seed_42",
    "status": "success"
}
```

has to be converted to:

```python
Model(
    controller="offset",
    run_id="2026-09-25_14-20-00_offset_no_rand_seed_42",
    seed=42,
    training_randomization=False,
),
```

Repeat this procedure for all 12 non-optimized training runs.

The final list must contain:

```text
3 × policy + no_rand
3 × policy + rand
3 × offset + no_rand
3 × offset + rand
```

using the seeds:

```text
0, 24, 42
```

For example:

```python
NON_OPTIMIZED_MODELS = [
    # --------------------------------------------------------
    # POLICY - NON RANDOMIZED
    # --------------------------------------------------------

    Model(
        controller="policy",
        run_id="<experiment_name for policy, no_rand, seed 0>",
        seed=0,
        training_randomization=False,
    ),

    Model(
        controller="policy",
        run_id="<experiment_name for policy, no_rand, seed 24>",
        seed=24,
        training_randomization=False,
    ),

    Model(
        controller="policy",
        run_id="<experiment_name for policy, no_rand, seed 42>",
        seed=42,
        training_randomization=False,
    ),

    # --------------------------------------------------------
    # POLICY - RANDOMIZED
    # --------------------------------------------------------

    Model(
        controller="policy",
        run_id="<experiment_name for policy, rand, seed 0>",
        seed=0,
        training_randomization=True,
    ),

    Model(
        controller="policy",
        run_id="<experiment_name for policy, rand, seed 24>",
        seed=24,
        training_randomization=True,
    ),

    Model(
        controller="policy",
        run_id="<experiment_name for policy, rand, seed 42>",
        seed=42,
        training_randomization=True,
    ),

    # --------------------------------------------------------
    # OFFSET - NON RANDOMIZED
    # --------------------------------------------------------

    Model(
        controller="offset",
        run_id="<experiment_name for offset, no_rand, seed 0>",
        seed=0,
        training_randomization=False,
    ),

    Model(
        controller="offset",
        run_id="<experiment_name for offset, no_rand, seed 24>",
        seed=24,
        training_randomization=False,
    ),

    Model(
        controller="offset",
        run_id="<experiment_name for offset, no_rand, seed 42>",
        seed=42,
        training_randomization=False,
    ),

    # --------------------------------------------------------
    # OFFSET - RANDOMIZED
    # --------------------------------------------------------

    Model(
        controller="offset",
        run_id="<experiment_name for offset, rand, seed 0>",
        seed=0,
        training_randomization=True,
    ),

    Model(
        controller="offset",
        run_id="<experiment_name for offset, rand, seed 24>",
        seed=24,
        training_randomization=True,
    ),

    Model(
        controller="offset",
        run_id="<experiment_name for offset, rand, seed 42>",
        seed=42,
        training_randomization=True,
    ),
]
```

The completed `NON_OPTIMIZED_MODELS` list has to be added to both:

```text
racetrack_benchmark_script.py
edgecase_benchmark_script.py
```

### 5.2 Optimized Models

Use the JSON log generated by:

```bash
python trainings_script.py --optimized
```

The procedure is identical to the non-optimized case. For every entry in the optimized training JSON log, create one corresponding `Model(...)` object inside:

```python
OPTIMIZED_MODELS = [
    ...
]
```

The field mapping is:

| JSON field           | `Model` field            | Mapping                                  |
| -------------------- | ------------------------ | ---------------------------------------- |
| `experiment_name`    | `run_id`                 | Copy directly                            |
| `policy_mode`        | `controller`             | Copy directly (`"policy"` or `"offset"`) |
| `seed`               | `seed`                   | Copy directly                            |
| `randomization_mode` | `training_randomization` | `"no_rand"` → `False`, `"rand"` → `True` |

For example, this optimized training entry:

```json
{
    "policy_mode": "policy",
    "seed": 24,
    "randomization_mode": "rand",
    "experiment_name": "2026-09-25_15-03-39_policy_rand_optimized_seed_24",
    "status": "success"
```

becomes:

```python
Model(
    controller="policy",
    run_id="2026-09-25_15-03-39_policy_rand_optimized_seed_24",
```

* `NON_OPTIMIZED_MODELS` uses the runs generated without `--optimized`.
* `OPTIMIZED_MODELS` uses the runs generated with `--optimized`.

## 8. Evaluation Output

All benchmark results are written to:

```text
evaluation/
```

The results are first separated according to the simulation model:

```text
evaluation/
├── non_optimized/
└── optimized/
```

Inside each directory, the results are separated into racetrack and edge-case evaluations:

```text
evaluation/
├── non_optimized/
│   ├── racetrack/
│   └── edgecase/
│
└── optimized/
    ├── racetrack/
    └── edgecase/
```

Each evaluation is additionally executed in:

* a non-randomized evaluation environment
* a randomized evaluation environment

The resulting directory structure is:

```text
evaluation/
├── non_optimized/
│   ├── racetrack/
│   │   ├── seeded_benchmark_no_rand/
│   │   │   └── plots/
│   │   └── seeded_benchmark_rand/
│   │       └── plots/
│   │
│   └── edgecase/
│       ├── seeded_benchmark_no_rand/
│       │   └── plots/
│       └── seeded_benchmark_rand/
│           └── plots/
│
└── optimized/
    ├── racetrack/
    │   ├── seeded_benchmark_no_rand/
    │   │   └── plots/
    │   └── seeded_benchmark_rand/
    │       └── plots/
    │
    └── edgecase/
        ├── seeded_benchmark_no_rand/
        │   └── plots/
        └── seeded_benchmark_rand/
            └── plots/
```

The benchmark scripts generate the evaluation CSV files and the corresponding plots inside these directories.

## 9. Complete Reproduction Procedure

The complete workflow for reproducing the experiments is therefore:

### 1. Add the supplied robot assets

```text
assets/robomaster/
assets/robomaster_optimized/
```

### 2. Train the 12 non-optimized policies

```bash
python trainings_script.py
```

### 3. Train the 12 optimized policies

```bash
python trainings_script.py --optimized
```

### 4. Generate the racetrack trajectories

```bash
python trajectory_generator.py
```

### 5. Generate the edge-case trajectories

```bash
python edgecases.py
```

### 6. Open the two generated training JSON logs

Extract the `experiment_name` of all training runs.

### 7. Configure the benchmark scripts

Add the non-optimized experiment names to:

```python
NON_OPTIMIZED_MODELS
```

and the optimized experiment names to:

```python
OPTIMIZED_MODELS
```

in both:

```text
racetrack_benchmark_script.py
edgecase_benchmark_script.py
```

### 8. Run the racetrack evaluations

```bash
python racetrack_benchmark_script.py
python racetrack_benchmark_script.py --optimized
```

### 9. Run the edge-case evaluations

```bash
python edgecase_benchmark_script.py
python edgecase_benchmark_script.py --optimized
```

### 10. Inspect the generated results

The complete evaluation results are available under:

```text
evaluation/
```
